AR-5RM Web Flasher

Backup, bootloader probe, and firmware flash for the Baofeng AR-5RM over a USB programming cable — straight from the browser, no scripts to run. Follows the tested radio_read.py → bootloader_probe.py → flash_bf.py sequence, in that order, enforced.
Checking Web Serial support…
Web Serial is not available in this browser. This tool needs Chrome or Edge on a desktop computer — Web Serial does not exist in Safari, Firefox, or on phones. Open this page there, plug in the programming cable, and reload. Everything below is disabled until then.

STEP 0 Connect the cable not connected

Plug the programming cable into the radio's K-connector (push it in firmly — Baofeng jacks need a hard seat) and into this computer. Then click Connect and pick the cable's serial port from the browser's list. The port runs at 115200 8N1, no flow control for every operation. Nothing is sent to the radio until you start an operation below.
No port selected.

STEP 1 Backup — factory memory idle

Radio state: stock firmware, powered ON, sitting at its normal main screen. This reads the radio's full factory memory image (33,664 bytes) using the stock CPS protocol (PROGRAMBFNORMALU). It is read-only — the tool refuses to send anything except the handshake and read frames. No backup, no flash: the flash step stays locked until a backup completes in this session.
⬇ Download factory_memory.img (33,664 bytes)
Waiting. The download link appears here once the full image is read.

STEP 2 Probe — bootloader handshake idle

Put the radio in flash mode first:
  1. Radio OFF.
  2. Hold both small side buttons next to PTT (not PTT itself) and keep holding.
  3. Power ON. The screen stays black — that is flash mode. Release the buttons.
The probe only sends the bootloader handshake frame and listens — it cannot write anything. The flash step stays locked until the bootloader answers in this session.
Waiting. Up to 5 handshake attempts; the first attempt that hears anything decides.

STEP 3 Flash — write a .BF package locked

Radio state: still in flash mode (black screen, from Step 2). Pick the prepared .BF package file. The tool mirrors the tested flash_bf.py: single-region packages only, strict header checks, and a SHA-256 prefix gate before the Flash button can arm.
NRF dev unit only. Flashing is one-way off stock — there is no verified factory image to restore from. Unit 1 (BK) must stay stock and unflashed; never run this on it.
